# Design a useful interface

## When to use

Use during plan, implement. Skip unrelated work and respect coordinator mode.

## Workflow

1. Identify the main task and primary action. Read existing tokens, controls and relevant screens before designing changes.
2. Preserve palette, icon family, typography and spacing rhythm. Improve alignment, hierarchy and concise labels before adding decoration.
3. Give information one clear home; group controls and reveal secondary details on demand. Keep approvals, questions and recovery visible; avoid repeated status cards.
4. Design real loading, empty, error and retry states. Put implementation details in diagnostics unless users need them to decide.
5. Inspect wide/narrow layouts, supported themes and enlarged text. Check focus, target sizes, contrast and overflow with long/empty content.
6. Use quiet active accents and short transitions. Stop ambient motion while hidden and remove motion for reduced motion; inspect captures with a capable visual reviewer.

## Verification and recovery

Name the improved flow and preserved conventions; report contrast measurements or image review only when performed. Repair the smallest failing token/component. Without image review, report structural checks and leave appearance unverified.

## Result packet

Primary flow; retained palette/type/icons; layout/state changes; viewport/theme/focus/contrast evidence; visual limits.
