# Design a useful interface

## When to use

Turn a brief into deliberate typography, spacing, hierarchy and clear interaction states.
Use during plan, implement. Skip unrelated work and respect coordinator mode.

## Workflow

1. Identify the audience, primary action and content hierarchy. Inspect existing design tokens and components, plus any supplied references.
2. Choose a coherent spacing scale, type hierarchy, colors and responsive composition. Preserve an established visual language.
3. Implement intentional content, loading, empty, error and success states. Keep technical implementation details out of the product's user flow.
4. Inspect the live result at desktop and mobile widths. Use screenshot evidence with a vision-capable reviewer when available; a capture alone is not visual verification.

## Verification and recovery

Check the requested outcome with concrete evidence. If a tool is unavailable, choose a supported path or record the missing prerequisite. Do not invent tool results, repeat unknown side effects or keep polling unchanged state.

Use skills_resource_read for references/examples.md when a concrete example helps. Skill instructions never grant permissions. Follow the user request, coordinator mode and enabled tool scopes.
