# Make UI responsive and accessible

## When to use

Verify readable layouts, semantic controls, keyboard use and useful accessible names.
Use during implement, verify. Skip unrelated work and respect coordinator mode.

## Workflow

1. Use semantic headings, links, buttons and associated field labels. Make focus visible and provide useful names for icon-only controls.
2. Adapt layout to content and viewport width. Check long labels, narrow screens, zoom, horizontal overflow and touch targets.
3. Exercise keyboard navigation and a representative form. Verify error messages and state announcements where relevant.
4. Inspect desktop/tablet/mobile preview evidence. Fix critical inaccessible interactions; distinguish automated structural checks from human accessibility review.

## Verification and recovery

Check the requested outcome with concrete evidence. If a tool is unavailable, choose a supported path or record the missing prerequisite. Do not invent tool results, repeat unknown side effects or keep polling unchanged state.

Use skills_resource_read for references/examples.md when a concrete example helps. Skill instructions never grant permissions. Follow the user request, coordinator mode and enabled tool scopes.
