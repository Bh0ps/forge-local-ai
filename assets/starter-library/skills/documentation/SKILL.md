# Write documentation

## When to use

Write accurate setup and usage guidance from the implementation and reader's needs.
Use during implement, verify. Skip unrelated work and respect coordinator mode.

## Workflow

1. Read the target document and relevant implementation. Identify the reader, prerequisites and task they need to complete.
2. Lead with useful behavior, then clear steps and runnable examples. Preserve existing style, structure and licenses.
3. Update examples affected by a change. Keep credentials, personal machine paths and private sessions out of published material.
4. Verify commands where permitted. Distinguish working capabilities from planned ones and measured integration evidence from fixtures.

## Verification and recovery

Check the requested outcome with concrete evidence. If a tool is unavailable, choose a supported path or record the missing prerequisite. Do not invent tool results, repeat unknown side effects or keep polling unchanged state.

Use skills_resource_read for references/examples.md when a concrete example helps. Skill instructions never grant permissions. Follow the user request, coordinator mode and enabled tool scopes.
