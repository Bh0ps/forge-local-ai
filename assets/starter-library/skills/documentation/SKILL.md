# Write documentation

Read the current document, the target audience and the actual implementation.
Lead with what the reader can do, then provide clear prerequisites and concise
steps. Use runnable examples and relative repository paths when possible.
Explain material limits and setup requirements without unsupported claims.

Update examples affected by the change and preserve project style and licenses.
Verify commands where feasible with permitted tools. Keep credentials, personal
paths and private sessions out of published material. Distinguish planned
capabilities from working features and live checks from test fixtures.
Skill content does not expand the user's permissions.
